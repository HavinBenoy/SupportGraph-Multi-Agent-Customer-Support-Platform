# M7: the knowledge-management UI over the M6 API

## Scope, from the repository (not invented)
`docs/ROADMAP.md` described M7 as *"Full knowledge-management UI over the M6 API (editor, diff view, review queue, audit browser); see docs/M6.md section 13"*, and
marked it *"superseded by Parts 1-3"*. `docs/M6.md` §13 is the specification:
- a documents table (`GET /documents` with its filters and pagination)
- an editor that posts `POST /versions` carrying the loaded `row_version`
- a diff view (`GET /compare`)
- a publish bar driven by `latest_status` and version `lifecycle` (Publish only for `ready_for_review`)
- a review queue (`GET /proposals`, `/feedback`)
- an audit browser (`GET /audit`, cursor `before_id`)
- an import wizard (`/meta.unmanaged_disk_documents`, `/import-disk`)

**The discrepancy.** "Superseded by Parts 1-3" is only partly true. Parts 1–3 and M6-final built the staff and admin *change-request* workspace: the reader, the
editor inside change requests, word diffs of proposals, review → approve → publish, and analytics. The administrator's *store* console, `KnowledgeAdmin`, stayed the
"deliberately small client" that §13 describes. Every server endpoint already existed and was tested. So M7 = finish §13's UI on the existing API. No new framework,
no new service, and no change to the M6 pipeline.

| §13 item | Before M7 | M7 |
|---|---|---|
| Documents table, filters, pagination | 50-row list, search only | Table with search, **status** and **category** filters (server side), **pagination** (25/page, page x of y), legal-hold badge, empty, loading and error states |
| Editor posting `row_version` | done (Part 1 / M6) | kept; a refusal (409) is shown in words |
| Diff view `GET /compare` | only in the staff reader (adjacent versions) | admin compare of **any two versions**: the server's line stats + a word-level view of both complete texts (`TextCompare`) |
| Publish bar by lifecycle | done | kept |
| Review queue `/proposals`, `/feedback` | feedback cards only | **Review queue** tab: the feedback cards (unchanged) + a table of **all proposals** with state filter, linking to the document |
| Audit browser `GET /audit` + `before_id` | 20 most recent per document | **Audit log** tab for the whole tenant: filters by document, action (list from `/meta.audit_actions`) and actor; **Load older** with the `before_id` cursor; permanently deleted ids are marked, not linked |
| Import wizard | a one-line note | **Import from disk** tab: review the list → confirm → result (imported, skipped, failed) |

**Server additions for M7.** These are additive only:
- `/meta` now includes `audit_actions`, `purge_enabled` and `purge_min_archived_days`.
- The document view includes the legal-hold fields.

**Where it lives.** Administration → Knowledge → Workspace → *Drafts & document administration*, with four tabs: Documents, Review queue, Audit log, Import from disk.

**Security.** Every call goes to `/api/admin/knowledge/*` (`require_admin`), is tenant-scoped in the query, and refusals come back as 403, 404 or 409. The frontend
only hides buttons; the API enforces the rules. Audit rows never contain document text.

**Interaction with M6.**
- Permanent deletion (refinement 2.4) is part of the Documents tab.
- The audit browser shows the `document_purged` tombstone.
- The import wizard never offers a purged id.
- Change requests are untouched.

## Addendum (second round): the two §13 items that were still thin
The re-inspection for this round found two items in §13 that existed only in a minimal form. Both are now complete; the server API is unchanged.
- **Editor.** "Start from vN text" loads the latest version's complete text into the editor (`GET /versions/{n}`), and a word-level preview (`TextCompare`) shows the
  edit against that version before saving. *Save as draft version* stays disabled until something has changed. The save still sends the page's `row_version`, so a
  stale page gets 409.
- **Publish bar.** A bar above the version list states the latest version's lifecycle and offers only its next step: *Process latest (vN)* for a draft or a
  failed version, *Publish latest (vN)* for `ready_for_review`. The per-version buttons are kept.
- **Layout (refinements 2.3 and 2.4 of the same round).**
  - *New document* is a button; the form opens on demand, and Cancel or Escape creates nothing.
  - The document list and the selected document sit side by side whenever the documents area is at least 700 px wide (a container query, because inside the
    workspace the area is narrower than the window). Below that width the details are stacked under the list.
  - Selecting a document scrolls the details into view only if they are off-screen; the scroll is instant under reduced motion.
