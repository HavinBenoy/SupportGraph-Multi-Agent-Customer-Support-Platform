# M2 - Browser voice line (simulated call)

A visitor or student opens `/voice`, presses **Start call**, and talks. The browser streams microphone audio to the API over a WebSocket; the
server finds the end of each question (Silero VAD), transcribes it (faster-whisper), runs it through **the same support graph as the text chat**,
and speaks the answer back (Piper). Everything said also appears as text, and the conversation is the same ticket as in the text chat.

```
 browser                                   FastAPI (/api/voice/ws)                              existing system
 mic -> AudioWorklet (16 kHz PCM16) --ws-->  Endpointer + Silero VAD  --utterance--> faster-whisper
                                                                                          | text
 speaker <- Web Audio queue <--ws-- Piper (sentence by sentence) <-- speakable(reply) <-- run_turn()  == POST /api/chat's code:
                                                                                          identity, RBAC, triage, router, FAQ, escalation floor,
                                                                                          write approvals, QA, analytics, rate limits
```

## What was built
| Piece | File |
|---|---|
| WebSocket route, identity, origin check, limits | `backend/app/api/routes/voice.py` |
| Call logic: pipeline, barge-in, limits (transport-independent) | `backend/app/voice/session.py` |
| Silero VAD (ONNX, no torch) + utterance endpointing | `backend/app/voice/vad.py` |
| Speech to text (faster-whisper, CPU int8) | `backend/app/voice/stt.py` |
| Text to speech (Piper, streamed per sentence) | `backend/app/voice/tts.py` |
| Spoken adaptation of a written reply | `backend/app/voice/text.py` |
| Real-model round trip check | `backend/app/voice/smoke.py`, `scripts/voice_smoke.py` (`make voice-smoke`) |
| Browser: capture worklet, player, socket client, call page | `frontend/public/voice-worklet.js`, `frontend/src/lib/voice.ts`, `frontend/src/components/VoiceCall.tsx`, `/voice` |

Silero VAD is the ONNX model that ships inside faster-whisper, run with onnxruntime. The `silero-vad` pip package is deliberately not used: it requires torch (~800 MB).

## Setup (once, needs internet)
```
make voice-setup          # pip install ".[voice]", downloads a Piper voice to models/voices and the Whisper model; prints two lines for your .env
# add the printed lines to YOUR .env:   SG_VOICE_PROVIDER=real   and   SG_VOICE_TTS_VOICE="…/models/voices/en_US-lessac-medium.onnx"
make voice-smoke          # Piper speaks 3 sentences, Silero must find each, Whisper must transcribe them back; writes evals/voice/REPORT.md
make api                  # restart the API (it reads .env at start)
make frontend-dev         # then open http://localhost:3000/voice (Chrome/Edge/Firefox; microphone needs localhost or https)
```
Nothing here edits `.env`, the database or any volume. The Whisper model (~145 MB for `base.en`) lands in the Hugging Face cache; Piper voices in `models/voices/` (git-ignored).
Other voices: `make voice-setup VOICE=en_US-amy-low` (faster) or any name from the Piper voice list. Other Whisper sizes: `SG_VOICE_STT_MODEL=tiny.en|small.en`.

## Protocol (`/api/voice/ws`)
Client: first `{"type":"start","tenant","token","ticket_id"}`, then binary PCM16 mono 16 kHz, optionally `{"type":"text","text"}` and `{"type":"stop"}`.
Server: `ready`, `speech_start`, `transcribing`, `transcript`, `thinking`, `reply` (text, status, citations, escalation id, timings), `audio_start` + binary PCM16 + `audio_end`, `interrupted`, `notice`, `error`.
`GET /api/voice/status` says whether the models are installed (the page shows what is missing instead of failing).

## Security and behaviour guarantees
- Identity is decided exactly as for the text chat: a bearer token gives tenant and student from the signed token (the claimed tenant is ignored); otherwise anonymous in the requested tenant. Tokens are re-checked against the account (disabled/role changed = refused). Ticket ids are signed and bound to that identity; a forged or someone else's ticket is refused. Staff tokens cannot use the student line.
- The voice path calls `run_turn` (the text chat's code), so RBAC, the escalation floor, abstention, citation validation, approvals and QA apply unchanged; spoken "talk to a person" escalates, a make-up request pauses for staff, own records need sign-in.
- Voice shares the text chat's per-student / per-address message budget, writes the same analytics events, and shares the same ticket (start by voice, continue by text, or the reverse).
- Browser WebSockets are not covered by CORS, so the server checks `Origin` against `SG_VOICE_ALLOWED_ORIGINS` / `SG_CORS_ORIGINS` / same host. Non-browser clients still need a valid token or ticket.
- Limits: 64 KB per audio message, audio faster than ~3x real time is refused, max utterance 15 s, 600 s and 60 turns per call (all configurable), typed text 1000 characters.
- Audio is processed in memory and never stored; only the text of the conversation is saved, like the chat. Speech models run on your machine (no cloud).
- The spoken version drops source ids, links and the sample-data notice, spells batch ids and reference numbers ("P Y F 1 0 1", "E S C dash …") and is capped at a sentence boundary; the written reply is unchanged.
- Barge-in: speech of at least `SG_VOICE_BARGE_IN_MS` while the assistant talks stops the audio at once (browser and server). Use headphones if your speakers feed back into the microphone (the browser's echo cancellation helps but is not perfect).

## Known limits (next: M3)
- Latency is the sum of VAD end-of-speech wait (0.7 s), Whisper (about 0.1-0.3x real time on base.en), the text path (about 4-8 s with the 1.7B model) and Piper's first sentence. Expect roughly 6-10 s from end of question to first audio. M3 targets this (streaming the answer, filler phrases, smaller silence window).
- No telephony yet (M4), no live human takeover (M4), no caller identity by phone number (M8).
- A noisy room can trigger the VAD; raise `SG_VOICE_VAD_THRESHOLD` (0.6-0.7) if it does. Whisper `base.en` is English-only.

## Troubleshooting
- "Voice is not ready on this server" on the page: it lists what is missing (usually `make voice-setup` not run, or `.env` lines not added / API not restarted).
- Microphone prompt does not appear: the page must be `http://localhost:3000` or `https://…`; check the browser's site permissions.
- The call connects but nothing is heard: check the terminal running `make api` (model load errors are logged); run `make voice-smoke`.
- Works on localhost but not behind another host name: add that page origin to `SG_VOICE_ALLOWED_ORIGINS` and set `NEXT_PUBLIC_VOICE_WS_URL` at build time (WebSockets go straight to the API, not through the Next proxy).
