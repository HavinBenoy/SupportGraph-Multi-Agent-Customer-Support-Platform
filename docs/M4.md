# M4 - Call sessions, staff Live Calls, listening and human takeover

> **Updated in M4.1.** The M4 "Return to AI" ability was removed completely: a call a person takes over stays with that person until it ends, fails or disconnects (sections 2.2, 2.6, 3, 6, 7 and 12 describe the current behaviour). The transcript, intervention feedback, exclusive control and hand-over announcement are in `docs/M5.md` (part A). `returning_to_ai` survives only as a legacy value so rows written by M4 stay valid.

Scope: every voice call becomes a durable **call session** with one clear audio owner at a time. Staff of the same tenant can see live calls, **listen**, **take over** (their microphone replaces the assistant, for good) and **end** it. Nothing about the assistant's reasoning changes: the same LangGraph, the same ticket/conversation, the same RBAC. No call recording, no stored audio, no voice-based identification.

## 1. Architecture in one picture

```
 caller browser <--ws /api/voice/ws--> voice route --> LiveCall (hub) <--> VoiceSession (the assistant: STT -> graph -> TTS)
                                                          |  owner: ai | staff | none     epoch: 1,2,3...
                                                          |
   staff browser #1 <--ws /api/staff/calls/{id}/stream----+   listeners (bounded outbox each)
   staff browser #2 <--ws ... -----------------------------+   at most one microphone (the owner's)
   staff browser  --REST /api/staff/calls[/{id}/listen|takeover|end|events|transcript|feedback]--> hub + database
```

| Piece | File | Job |
|---|---|---|
| Tables | `app/db/models.py` (`Call`, `CallEvent`), migration `0006_calls` | the durable record: status, owner, epoch, timestamps, audit events |
| State machine | `app/calls/state.py` | the allowed moves; every move is an atomic compare-and-set `UPDATE ... WHERE status = :expected` |
| Service | `app/calls/service.py` | create/read/list/finish, events written in the same transaction as the move, startup sweep |
| Hub | `app/calls/hub.py` | live audio ownership, listeners, staff microphone, grace period, end |
| REST + staff socket | `app/api/routes/calls.py` | authorization, tenant isolation, the staff audio WebSocket |
| Voice hooks | `app/voice/session.py`, `app/api/routes/voice.py` | register the call; suspend/resume the assistant; tap the caller's audio |
| UI | `frontend/src/components/LiveCalls.tsx`, `frontend/src/lib/live.ts` | Live Calls tab in the staff console |

## 2. Design decisions (and why)

1. **Listening is not a state.** Any number of staff may listen while the assistant or a staff member owns the call, and a listener coming or going changes nothing about who speaks. Modelling it as a state (`staff_listening`) would need combinations (listening during takeover, two listeners, one leaves). So the persisted states are only about ownership: `created`, `active_ai`, `staff_takeover`, `ended`, `failed` (plus the legacy `returning_to_ai`, never entered any more). Listeners are visible live (`listeners`, `listening_staff`) and in the audit trail (`listen_started` / `listen_stopped`).
2. **Ownership only moves one way (M4.1).** `created -> active_ai -> staff_takeover -> ended|failed`. M4 also had a `returning_to_ai` hand-back; it was removed because a human who has taken over a call must never be silently replaced by the assistant. The status value is kept only so that rows written by M4 stay legal; the application never moves a call into it, and the API has no return route.
3. **The database is the referee for races; an asyncio lock per call orders things inside this process.** The compare-and-set is what stops two staff taking the same call even across processes (tested with 8 real concurrent Postgres transactions). The per-call lock makes listen/takeover/end sequential, so they cannot interleave in memory.
4. **Ownership epoch.** Every move bumps `epoch` (database and memory). A staff microphone must prove it knows the *current* epoch: `mic_open` carries it and every audio message is prefixed with it. A frame from a previous takeover (replayed, delayed, from a stale tab) is dropped and counted, and a socket that keeps sending them is closed.
5. **State lives in this process.** The audio is in memory, so a call is only live in the process that holds its WebSocket. At startup any call still marked live belongs to a process that no longer exists and is marked `failed` (`server_restart`). Run one API worker (as `make api` does); multi-worker needs a shared bus and is out of scope.
6. **Staff presence has a grace period** (`SG_CALLS_TAKEOVER_GRACE_S`, default 15 s). After a takeover the owner must have an open audio connection. If it is missing for the grace period (tab closed, never opened, network lost, token expired) the call **ends** as `failed` (reason `staff_unreachable`): it does not go back to the assistant and it is not handed to another staff member, so the caller is never left in silence and never silently moved. A page refresh inside the grace period keeps the takeover.
7. **The assistant's time limit counts only the assistant's time.** `SG_VOICE_MAX_SESSION_S` protects the assistant's resources, so seconds under staff ownership are not counted (a long human conversation is not cut off at 10 minutes); the turn limit and the audio-rate guard are unchanged.
8. **The voice line never depends on M4.** If the `calls` tables are missing (migration not applied) the call still works exactly as before and the log says to run `make db-migrate`.
9. **Privacy by construction.** Event details accept only a fixed set of short scalar keys (`reason`, `role`, `epoch`, `listeners`, `previous_owner`, `duration_s`, `connection`, `status`), so text or audio cannot be stored by mistake. The API returns `ticket_ref` (a 10-character reference to recognise the conversation), never the ticket id (an anonymous ticket id is a capability to continue that chat). `student_id` is only returned to admins. Staff hear audio and see short transcript lines of calls of **their own tenant**; none of it is logged, stored or written to disk.

## 3. Call lifecycle and ownership state machine

```
created --connected--> active_ai --takeover--> staff_takeover
   any non-terminal state --end--> ended        any non-terminal state --fail--> failed        (ended / failed are terminal; no way back to active_ai)
```

| Event | Moves | Owner afterwards | Epoch |
|---|---|---|---|
| caller connects, call registered | (new) `created` | none | 0 |
| session started, `ready` sent | `created` -> `active_ai` | assistant | +1 |
| staff takes over | `active_ai` -> `staff_takeover` | that staff member | +1 |
| staff ends / caller hangs up / goodbye / limit | any live -> `ended` | nobody | +1 |
| error, server restart, owner unreachable | any live -> `failed` | nobody | +1 |

Idempotency: repeating *your own* takeover, an end of an ended call, or a listen on a call you already listen to returns the current state with no new event and no error. A second staff member taking a held call gets **409** and a `takeover_failed` event. A takeover/listen on an ended call gets **409**. Timestamps: `created_at`, `connected_at`, `takeover_at`, `ended_at` (`returned_at` exists only on legacy rows).

## 4. How listening works

1. The UI calls `POST /api/staff/calls/{id}/listen`: the server checks role, tenant and that the call is live, and returns where to connect.
2. The UI opens `ws /api/staff/calls/{id}/stream`. Browsers cannot send headers, so the first message is `{"type":"auth","token":...}`; **Origin** is validated before the handshake; role must be staff/admin; the call is looked up *by tenant*, so another tenant's call is "not found or already ended" (the same words as an ended call, so nothing leaks).
3. The staff member joins the call's listener set (limit `SG_CALLS_MAX_LISTENERS`). `listen_started` is recorded.
4. They receive: caller microphone audio (tag 1, 16 kHz PCM16), the assistant's audio (tag 2, same frame as the caller gets), another staff member's voice (tag 3), short transcript lines, ownership changes, `call_ended`.
5. The caller's audio reaches the assistant exactly as before; the tap is synchronous and cannot block or raise into the call. Each listener has its own bounded outbox: a slow listener drops **its own** oldest audio.
6. Closing the tab or pressing Stop listening removes the listener (`listen_stopped`); the call is untouched. The socket also closes when the staff token expires or the account is disabled (re-checked every `SG_CALLS_RECHECK_S`).

## 5. How takeover works

`POST .../takeover` -> hub, under the call's lock:
1. refuse if ended; if the caller already holds it, return the current state (idempotent); if another staff member holds it, record `takeover_failed` and answer 409;
2. database compare-and-set `active_ai -> staff_takeover` (+ `takeover_succeeded` event in the same transaction);
3. **one synchronous block**: owner = staff, epoch = new epoch, `VoiceSession.suspend_ai(epoch)`: the speech in progress is cancelled, the pending turn and all queued turns are dropped, the endpointer is reset, the session is marked suspended. A graph run that is still in flight is allowed to finish but its reply is discarded (never shown, never spoken). A response is never sent a single frame after the epoch moved (the session checks before every frame, and the hub checks `owner == ai` again);
4. the caller is told (`interrupted{reason:"takeover"}`, `ownership{owner:"staff"}`) and the grace timer starts.
5. The staff browser sends `mic_open{epoch}`. The hub accepts it only from the owning account, on an attached socket, with the current epoch; a staff turn id is reserved from the **same counter** as the assistant's (so the caller's player, which drops responses older than the newest turn it has seen, plays it), and the caller gets `audio_start{staff:true, sample_rate:16000}`. Each microphone message (`uint32 epoch` + PCM16) is validated (owner, mic connection, epoch, size, real-time rate) and forwarded to the caller as an ordinary audio frame; other listeners hear it too.
6. While staff own the call, the caller's audio is **forwarded to staff only**: no VAD, no STT, no graph, no reply. Typed text in the voice call is declined with a notice.

## 6. There is no return to the AI (M4.1)

M4 let the staff member (or an admin) hand a call back to the assistant. That ability is gone from the button, the frontend action, the API route and the backend: `POST /api/staff/calls/{id}/return` does not exist, the hub has no such method, and a test asserts the state machine has no path into `active_ai` from `staff_takeover`. The only ways a human-owned call stops being human-owned are **end** (by the owner), **caller disconnects**, **failure**, or **the owner's connection staying away past the grace period** (ends as `failed`). Only the intervention owner may end a call they took over (an admin may end an AI-owned call, not a human-owned one).

## 7. Failures and disconnects

| Situation | Behaviour |
|---|---|
| takeover during assistant speech | speech cut, no further assistant frame, queued turns dropped |
| takeover while the graph is running | reply discarded |
| two staff take over together | exactly one wins; the other gets 409 + `takeover_failed` |
| staff tab closed / refreshed / network lost | microphone un-routed at once; grace period; a reconnect inside it keeps the takeover; otherwise the call ends as `failed` (`staff_unreachable`); it is never returned to the assistant |
| staff token expires / account disabled | staff socket closed with `session expired`/`session ended`, then as above |
| staff never opens a microphone | same grace period, then the call ends as `failed` |
| second microphone connection of the same staff member | replaces the first |
| caller disconnects | call `ended` (`caller_disconnected`), `participant_disconnected` event, staff sockets told and closed |
| goodbye / session limit | `ended` (`goodbye`, `limit`) |
| unexpected error in the voice handler | `failed` (`error`); persisted even if the handler is cancelled |
| assistant turn raises | error message to the caller, call carries on, takeover still possible |
| caller socket send fails during an ownership change | ignored; the route ends the call |
| event write fails | logged; the call continues |
| server restart / shutdown | shutdown ends live calls cleanly; startup marks leftovers `failed` (`server_restart`) |
| end during takeover | everything stops, sockets closed, state persisted; later requests get 409 |

## 8. Security and privacy

* Staff/admin only (`require_staff`): no token 401, student 403. Tenant comes from the signed token; another tenant's call is 404 on every route and "not found" on the socket.
* WebSocket: token in the first message, 10 s to authenticate, Origin validation, role check, tenant-scoped lookup, expiry and account re-check, listener cap, microphone rate/size limits, stale-frame limit.
* Ownership: only the current owner's microphone connection with the current epoch reaches the caller; a staff member attached to call A cannot reach call B (a connection is bound to one call object).
* Logs: only ids, counts and reasons. The voice session already logs events without words; the hub logs nothing about content; a test captures the logs of a full call and asserts the spoken question and the token are absent.
* Data: nothing recorded or persisted except the `calls` row and event rows; no audio, no transcript, no voice-based authentication. Staff transcript lines are streamed live, capped at 500 characters, and not stored.

## 9. Database changes

Migration `0006_calls` (additive; downgrade drops exactly `call_events` then `calls`; verified up/down on Postgres with data present):
`calls(tenant_id, id, ticket_id, student_id, status, owner, owner_subject, epoch, created_at, connected_at, takeover_at, returned_at, ended_at, end_reason)` with CHECKs on `status` and `owner`, primary key `(tenant_id, id)`, FK to `tenants`, index `(tenant_id, status)`;
`call_events(id, tenant_id, call_id, kind, actor, detail JSON, created_at)` with a composite FK `(tenant_id, call_id) -> calls`, index `(tenant_id, call_id, id)`. No existing migration, table or row is touched. Apply with `make db-migrate`.

## 10. Configuration and dependencies

No new dependency. Optional settings (all in `.env.example`, defaults shown): `SG_CALLS_TAKEOVER_GRACE_S=15`, `SG_CALLS_MAX_LISTENERS=5`, `SG_CALLS_LISTENER_QUEUE=200`, `SG_CALLS_RECHECK_S=30`, `SG_CALLS_KEEP_ENDED_MINUTES=30`, `SG_CALLS_STAFF_FRAME_MAX=16384`. No model, embedding, voice-engine or `.env` change.

Also in this change set (M3.1): the nomic embedder is now loaded with the same `keep_alive` as the chat model (`SG_LLM_KEEP_ALIVE`, converted to seconds because `OllamaEmbeddings` takes an integer), so Ollama stops unloading it after 5 idle minutes (your `ollama ps` showed only `qwen3:1.7b`).

## 11. API and socket reference

REST (staff/admin): `GET /api/staff/calls`, `GET /api/staff/calls/{id}`, `POST /api/staff/calls/{id}/listen|takeover|end`, `GET /api/staff/calls/{id}/events?limit=`, and (M4.1) `GET .../transcript`, `GET|POST|PUT .../feedback`, `POST .../feedback/skip`, `GET /api/staff/interventions`. Call object: `id, short_id, status, owner, owner_staff, epoch, ticket_ref, caller, created_at, connected_at, takeover_at, ended_at, end_reason, duration_s, live, listeners, listening_staff, mic_open, is_mine, listening` (+ `student_id` for admins). Socket protocol: the docstring of `app/api/routes/calls.py`. Caller socket additions: `ownership{owner,epoch}`, `audio_start/audio_end` with `staff:true`, `call_end{reason:"ended_by_staff"}`.

## 12. Manual verification in a browser (needs your machine: microphone, speakers, Ollama)

Use **two browser profiles or windows**, headphones on the staff side (avoids echo).
1. `make db-migrate`, `make api`, `make frontend-dev`. Migration 0006 should apply with no other change.
2. Window A (caller): open `/voice`, press **Start call**, allow the microphone, ask "Can I pay the fee in instalments?" You should hear the answer.
3. Window B (staff): sign in as `staff1`, open **Staff console -> Live calls**. The call is listed: short id, "Assistant on call", started time, running duration, owner "Assistant", a student/visitor reference.
4. Select it, press **Listen**. Within a second the status shows "You are listening". Ask another question in window A: you hear the caller and the assistant in window B, and the transcript lines appear. Window A is unaffected.
5. While the assistant is mid-answer (ask something long), press **Take over**. The assistant must stop within a moment and not resume; window A shows "A staff member has joined your call" and the typing box is disabled. Allow the staff microphone when asked.
6. Speak in window B: window A hears you. Speak in window A: window B hears you; the assistant says nothing.
7. Press **Mute microphone** / **Unmute microphone**: window A hears nothing / hears you again.
8. Check there is **no Return to AI** control anywhere (list, detail, menus). The assistant stays silent for the rest of the call.
9. Close window B's tab. Wait about 15 seconds: the call ends; the assistant does not come back, and the list shows the call as **Ended after intervention** (red).
10. On a new call, take over from `staff1`, then open it as `admin1` in a third window: Take over and End call are disabled and the page says only staff1 can speak on it or end it.
11. Press **End call** (then confirm): window A shows "The call was ended by a staff member", the list shows the call as Ended with "ended by staff". Try Take over/Listen: disabled.
12. Start a call again and hang up from window A: window B shows the call as ended (caller hung up) within a few seconds.
13. Check the trail: `curl -H "Authorization: Bearer <staff token>" http://localhost:8000/api/staff/calls/<id>/events` shows created, connected, listen_started, takeover_requested, takeover_succeeded, ended.

## 13. Known limitations

* Verified in the sandbox with fake STT/TTS/VAD and synthetic audio, a fake browser audio layer and real FastAPI sockets. **Real microphones, speakers, echo, jitter, browser autoplay rules and Ollama are not exercised there**; section 12 is the real check.
* One API process. Live state is in memory (section 2.5); a restart ends live calls.
* Staff audio is 16 kHz mono with a short jitter buffer (150 ms at the caller). On a bad network a human voice may glitch; there is no adaptive buffer.
* The human conversation is not transcribed or given to the assistant (privacy). The M4.1 transcript shows when staff spoke, never their words; the post-call intervention feedback form is where staff record what was wrong.
* A caller who reconnects starts a *new* call session on the same ticket (the conversation continues, the call record is new).
* Caller-side echo cancellation is the browser's; if staff use speakers the caller may hear an echo.
* Staff transcript lines come from the assistant's own transcript events, so only assistant-handled speech is transcribed; staff-vs-caller speech during a takeover is audio only.
* Trial metrics, consent and recording are described in `docs/M5.md`.
