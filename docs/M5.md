# M4.1 + M5 - Intervention workflow and Trial Verification Mode

One change set (`supportgraph-m4.1-m5-complete.zip`). Part A is M4.1 (a safer, clearer human takeover), part B is M5 (a trial mode with disclosure, explicit recording consent, retention and metrics). No model, embedding or RAG change; no new paid service; no new Python or npm dependency.

## A. M4.1

### A1. Return to AI is gone
Removed from the button, the frontend action (`api.returnCall`), the REST route, the hub method and the state machine. A call a person takes over stays theirs until it **ends** (by them), the **caller disconnects**, it **fails**, or **their connection stays away longer than `SG_CALLS_TAKEOVER_GRACE_S`** (it then ends as `failed`, reason `staff_unreachable`). It never goes back to the assistant and is never given to another staff member. `returning_to_ai` stays a legal value in the database CHECK only so rows written by M4 remain valid; nothing moves a call into it.

### A2. Exclusive control by the intervention owner
`calls.intervention_owner` (migration 0007) is written in the same compare-and-set as the takeover and never cleared. Every control path re-checks it against the database, not just memory: end, microphone, feedback. Only the owner can speak or end the call; other staff and admins can listen. An admin may take over an **AI-owned** call, but cannot take or end a **human-owned** one. Two simultaneous takeovers: exactly one wins, the other gets 409.

### A3. Hand-over announcement
Text (`SG_CALLS_HANDOVER_ANNOUNCEMENT`, default): "I want to make sure you receive accurate information. One of our support specialists is joining us to clarify this. I'll hand over the conversation now."
* Played in the assistant's voice **only after** ownership has been granted in the database, so a refused takeover never announces anything.
* Recorded as a **system** entry in the transcript, never as an AI message and never sent to the language model.
* Audio gates: while `announcing` the staff microphone is refused (`mic rejected: announcing`) and the browser queues the request and opens the microphone when the announcement ends, so the two never overlap. If the announcement fails or exceeds `SG_CALLS_ANNOUNCEMENT_TIMEOUT_S` the gate opens anyway (a failure never blocks the human) and the failure is audited and shown to staff.
* Listening staff see "announcement playing"; its audio is not mirrored to listeners.

### A4. Full transcript
`GET /api/staff/calls/{id}/transcript` (staff/admin, same tenant only; another tenant gets 404). It is built from data that already exists: the conversation messages in the LangGraph checkpoint thread of the call's ticket (customer and AI, with timestamps where the history has them) merged chronologically with the call's events (takeover, announcement, end, ...). Staff speech appears only as **spans** ("Spoke to the caller, 10 s") because staff audio is never transcribed. Nothing is invented: if a timestamp is missing the entry says so; the response carries `notes` with these limits and the page shows them. Not stored anywhere new; not logged.

### A5. Status colours (with words)
| Category | Colour | Label | When |
|---|---|---|---|
| `ai_handling` | green | AI handling | live, AI owns audio (listening does not change this) |
| `human_handling` | blue | Human handling | live, a person owns audio |
| `ended_normally` | grey | Ended normally | ended without a takeover |
| `ended_after_intervention` | red | Ended after intervention | ended (or failed) after a takeover |
A fifth, amber `failed` is used for a call that failed without any human involvement, so it is not mistaken for an intervention. Colour is never the only signal.

### A6. Post-call "Call intervention feedback"
Shown only to the **intervention owner**, only **after the call has ended** (never during it, never to anyone else, admins included for writing). Prompt: "What did the AI say or do that required your intervention?" plus a required category (incorrect factual information, outdated knowledge, misleading response, policy or compliance issue, customer dissatisfaction, missing knowledge, other), an optional "correct information" field and an optional pointer to the AI message concerned (from the call's own transcript).
* One record per call (primary key `(tenant_id, call_id)`): **no duplicates**. Submit is a compare-and-set from `awaiting|skipped`; a second submit is refused. **Skip** records that none was given and can still be followed by a submit. **Edit** is allowed until an administrator has reviewed it.
* The text is a **proposed correction, not verified knowledge**. Review statuses: `pending_review -> reviewed -> approved_for_update | rejected` (and `pending_review -> approved_for_update | rejected`; `approved_for_update -> rejected`). Review is admin-only, an administrator **cannot review their own feedback**, every change is kept in `feedback_reviews`.
* **Nothing in this flow writes to the knowledge base or the vector index.** "Approved for knowledge update" is a label for a later, manual, M6 step.
* Staff see their own records in Staff console > "My intervention feedback" (`GET /api/staff/interventions`).

## B. M5 Trial Verification Mode

### B1. Architecture
```
 admin UI --PUT /api/admin/trial (expected_version)--> trial_settings (versioned) + trial_events (audit)
 caller WS --connects--> LiveCall --TrialCall.start()--> trial_notice (disclosure text + audio, recording offer if allowed)
 caller WS --{"type":"consent","decision","policy_version"}--> consent.decide() --granted--> CallRecorder --> RecordingProvider (none | local)
 retention loop / admin button / make purge-trial --> retention.run_purge() --> provider.delete + tombstones
 admin UI --GET /api/admin/trial/metrics|feedback|retention|recordings--> counts only
```
| Piece | File |
|---|---|
| Settings + audit | `app/trial/settings.py` |
| Consent state machine | `app/trial/consent.py` |
| Per-call disclosure/consent/recorder | `app/trial/call.py` |
| Provider abstraction, recorder | `app/trial/recording.py` |
| Retention and purge | `app/trial/retention.py` |
| Metrics | `app/trial/metrics.py` |
| API | `app/api/routes/trial.py` |
| Feedback | `app/calls/feedback.py` |
| UI | `TrialAdmin.tsx`, `FeedbackForm.tsx`, `Transcript.tsx`, `MyInterventions.tsx`, `CallStatus.tsx`, `VoiceCall.tsx` |

### B2. Trial switch
Admin only. Stored per tenant with a `version`; `PUT` must send `expected_version` and a stale value gets **409** (no lost update). Strict types: `"yes"` or `1` never switches anything on. Every change writes a `trial_events` row (actor, kind, changed field names, no text). A call reads the settings **when it starts** and keeps that mode; switching the trial off or recording off stops any live recording at once. Staff can read only `GET /api/staff/trial` (`enabled`, `recording_offered`), never change it. Defaults: off, nothing recorded.

### B3. Disclosure and consent
* The disclosure ("this is a trial call ...", editable) is shown as text and spoken by the assistant at the start of every trial call.
* Recording is a **separate, explicit** question shown only if (a) trial mode is on, (b) "recording offered" is on, and (c) a provider is configured and healthy. The caller answers with a button; speech, silence, typing or any staff/admin action can never grant it. Decisions: `offered`, `granted`, `declined`, `withdrawn`, each stored with the **policy version** the caller saw. The policy version increases when the notice text, the recording period or the withdrawal rule changes, and a decision made against an old version is refused, so consent always refers to the exact terms shown.
* **Declining or ignoring does not affect the call** (same assistant, same staff features).
* A caller can **withdraw** at any time during the call: recording stops immediately; the admin-chosen policy then deletes what was recorded (`delete`) or keeps it until it expires (`keep_until_expiry`).
* The product makes **no claim of legal compliance**. What your organisation must tell callers, and whether it may record at all, is for the organisation (and its lawyers) to decide; the notice text is editable for that reason.

### B4. Recording
`RecordingProvider` protocol: `NullProvider` (default; nothing is ever written) and `LocalProvider` (WAV files under `SG_TRIAL_RECORDINGS_DIR`, directory 0700, files 0600, references validated against traversal). Never in the database (only metadata and an opaque reference), never in logs. **Fails closed**: if storage fails the recorder is dropped, the recording is marked `failed`, the caller is told, the call continues unrecorded. Three tracks (customer, AI, staff). A size cap (`SG_TRIAL_RECORDING_MAX_MB`) stops it with reason `size_limit`. Download is admin-only, audited (`recording_accessed`) and `Cache-Control: no-store`; no response ever shows a storage reference.

### B5. Retention and purge
`run_purge` is **idempotent**: recordings past `expires_at`, consent records older than `retention_consent_days`, reviewed/skipped feedback older than `retention_feedback_days`. A recording under **legal hold** is never deleted. A failed deletion keeps the row, increments `purge_attempts`, records a short error code and is **retried on every run** without blocking the others. A purged recording leaves a tombstone row (no audio, no storage reference). Calls, tickets and knowledge documents are never touched. The audit entry holds **counts only**. Triggers: the in-process loop (`SG_TRIAL_PURGE_INTERVAL_MIN`, 60 default, 0 = off), the admin "Delete expired data now" (with a **preview** / dry-run), and `make purge-trial`. The admin view shows policy, counters (kept, due, held, failing), the last run and each recording's status, with place/release legal hold (reason required).

### B6. Metrics
`GET /api/admin/trial/metrics?from=YYYY-MM-DD&to=YYYY-MM-DD` (UTC, inclusive, default last 30 days, max one year). Only calls made **in trial mode** are counted. Counts and rates only: calls, AI-handled, listener sessions, takeovers (listening is not a takeover), intervention rate, ended normally / after intervention / failed, escalations, average durations, consent funnel, recordings, feedback by category and review status. **No names, ids, text or audio.** Empty period -> explicit empty state; a rate with no denominator is `null` ("n/a", never 0%). A row cap (`SG_TRIAL_METRICS_MAX_ROWS`) marks the result `truncated`.

### B7. Security measures
Admin-only routes (`require_admin`), staff read-only flag, tenant from the signed token on every query (another tenant's recording, feedback or call is 404), strict request models with `extra="forbid"`, strict booleans/ints, compare-and-set on settings and feedback, consent only from the caller's own call connection with the matching policy version, owner re-check against the DB for every human control, no secrets/ticket ids/storage references in responses, audit events with scalar keys only, nothing personal in logs (a test inspects logs of a full trial call with recording).

## C. Database migrations (additive; `make db-migrate`)
* **0007** `interventions`: `calls.intervention_owner` (nullable), `intervention_feedback`, `feedback_reviews`.
* **0008** `trial_mode`: `calls.trial_mode` (boolean, default false), `trial_settings`, `trial_events`, `call_consents`, `call_recordings`.
Downgrades remove exactly what they add. Tested up -> down -> up on PostgreSQL 16 and on SQLite (see TESTING.md for the SQLite starting-point caveat: migrations 0001-0003 use PostgreSQL-only DDL).

## D. API summary
Staff/admin: `GET /api/staff/calls/{id}/transcript`, `GET|POST|PUT /api/staff/calls/{id}/feedback`, `POST .../feedback/skip`, `GET /api/staff/interventions`, `GET /api/staff/trial`. **Removed:** `POST /api/staff/calls/{id}/return`.
Admin: `GET|PUT /api/admin/trial`, `GET /api/admin/trial/events|metrics|feedback|retention|recordings`, `POST /api/admin/trial/feedback/{call_id}/review`, `POST /api/admin/trial/retention/purge`, `POST /api/admin/trial/recordings/{id}/hold`, `GET /api/admin/trial/recordings/{id}/audio/{track}`.
Caller socket: new `trial_notice`, `recording` messages; new inbound `consent`. Staff socket: new `announcement{started|finished|failed}`, `owner_disconnected{grace_s}`; microphone `rejected` with reason `announcing`.

## E. Configuration
`.env.example` gains (all optional, defaults shown): `SG_CALLS_HANDOVER_ANNOUNCEMENT`, `SG_CALLS_ANNOUNCEMENT_TIMEOUT_S=30`, `SG_TRIAL_RECORDING_PROVIDER=none`, `SG_TRIAL_RECORDINGS_DIR=data/recordings`, `SG_TRIAL_RECORDING_MAX_MB=200`, `SG_TRIAL_PURGE_INTERVAL_MIN=60`, `SG_TRIAL_METRICS_MAX_ROWS=5000`. To try recording locally set `SG_TRIAL_RECORDING_PROVIDER=local`; keep `data/recordings/` out of git (now in `.gitignore`) and out of any backup you do not control. `.env` is never touched by this change set.

## F. Manual verification in a browser (your machine: microphone, speakers, Ollama)
1. `make db-migrate`, `make api`, `make frontend-dev`. Sign in as `admin1`: Admin console > **Trial verification**: mode shows OFF, "No recording provider ... never recorded".
2. Turn trial mode **on**. Open `/voice` in window A, start a call: the disclosure is shown and spoken; **no** recording question appears (not offered). Ask a question; end the call. Admin metrics: 1 trial call.
3. Stop the API; set `SG_TRIAL_RECORDING_PROVIDER=local` in your `.env`; restart. In Trial verification tick **Offer callers the choice to record**, set recording days to `1`, Save. New call: the notice and **Allow recording / No thanks** appear. Choose **No thanks**: the call carries on identically, nothing is recorded.
4. New call, choose **Allow recording**: "Recording is on." appears; speak, then press **Stop recording** (withdraw): recording stops. Admin > Recordings shows the recording and, per the withdrawal rule, deleted/kept.
5. New call, agree, end the call: a recording row with size and expiry; download is not offered in the UI (use the audited endpoint if you need it).
6. **Place legal hold** with a reason on it; **Preview what would be deleted**, then **Delete expired data now**: the held one is skipped.
7. Window B (`staff1`): Live calls > listen, **Take over**: the caller hears the hand-over announcement, your Enable microphone stays off until it ends. Open as `staff2`/`admin1`: only listen. Close B's tab for ~15 s: the call ends (red, "Ended after intervention"), the assistant does not return.
8. As `staff1` > the ended call > **Call intervention feedback** appears: submit with a category. `staff2` sees no form. As `admin1` (not the author) open Trial verification > Intervention feedback and approve it; the knowledge documents are unchanged.
9. Set the date filter in Trial metrics to a day without calls: the empty state appears.

## G. Known limitations
* All automated checks ran in the sandbox with fake STT/TTS/VAD, **synthetic audio** and a fake browser audio layer. Real microphones, speakers, echo, jitter, browser permission prompts, real Ollama latency, and the **real audio quality, file sizes and playback of recordings** have not been exercised.
* Recording works only with the local-disk provider. There is no encryption at rest, no off-machine storage and no audio playback in the UI; disk encryption and backup policy are yours.
* The retention loop runs inside the single API process; if it is down, the next start catches up. Deletion of files is best-effort at the filesystem level (no secure wipe).
* Staff speech is not transcribed; the transcript shows only that it happened and for how long.
* The transcript depends on the conversation history kept by the existing LangGraph checkpoint; very old or pruned threads may give a shorter transcript (the response says when it is incomplete).
* The announcement is not mirrored to listening staff.
* An administrator cannot take over or end a human-owned call (by design); if the owner is unreachable the call ends after the grace period.
* The compliance of recording with any law or contract is not assessed here.
