# M2.1 - Conversational polish and call intent handling

Real voice testing showed four problems: a robotic reply to "Hi", "That's it, you can stop the call" answered with a knowledge-base abstention,
"Please forward this call towards your supporting" answered with an unrelated FAQ, and "I am just testing" answered with an abstention.
All four had the same cause: every utterance was sent to the model-based triage and, unless it looked like an escalation, to retrieval.

## Where the fix lives (one shared layer)
`app/graph/support.py`, the support graph that the text chat and the voice line both call. Nothing is duplicated in the voice code.

```
START -> triage --- code first: injection screen, escalation floor, then conversation intent (no model call for a match)
          |
        route ---> escalate | converse (NEW) | clarify | knowledge | action | write  -> qa -> finalize
```
- `app/conversation/intents.py` (new, pure code): `greeting`, `thanks`, `acknowledgement`, `goodbye`, `interruption` ("just testing", "never mind", "wait", "that's not what I asked"). An utterance counts only if **every sentence** is such a phrase; "Thanks, what is the fee?" has a real question, so the normal flow handles it. Unpunctuated speech ("okay thank you that's it") works.
- `converse` branch (`graph/support.py`): fixed replies from `graph/nodes/replies.py` (`CONVERSE`, several variants, picked by how many replies the conversation already has). No retrieval, no model, no tools. `goodbye` sets `end_call`.
- Human support: the existing `human_request` rule of the escalation floor (`guardrails/escalation_floor.py`) was widened for spoken wording: forward/transfer/connect/put me through ... to support/a person/agent/representative/manager/counsellor, "I need to contact support", "get me a human", "customer care", "I don't want to talk to a bot". Look-alikes ("How can I contact the support team?", "transfer my fee", "talk to someone who teaches Java") do not fire (tests). A match skips the triage model call, escalates with the existing escalation/brief/team routing, and uses honest wording: no live transfer exists yet (M4), so the reply says a note was passed to the team with a reference.
- Voice: the `reply` carries `end_call`; after the closing is spoken the server sends `call_end` and closes; the page lets the audio finish, then hangs up without an error banner. Barge-in is unchanged: the interrupting utterance is simply handled like any other (and "I am just testing" is acknowledged).
- Goodbye while a staff approval is pending (`graph/review.py`): the call may end; the request stays pending and the outcome appears in the conversation.

## Order of precedence (safety first)
1. injection screen -> refuse (a "say bye" injection is not a goodbye)
2. escalation floor / model escalation -> escalate ("bye, someone is following me" still escalates)
3. conversation intent -> converse
4. everything else exactly as before (triage -> routing -> RAG/tools/write; citations, abstention, RBAC, approvals, QA unchanged)
"yes"/"no" are never pleasantries (they answer a pending confirmation) and a bare "stop" stays the caller's barge-in.

## Evaluation datasets
`T052` ("Thanks, that was helpful!") and `T144` ("hello") were labelled `expected_route: clarify` (the old fixed-wording branch); they are now `converse`, scored with the same bar as clarify (no tools, no leak, no answer). Gates and the reference are unchanged: the offline regression gate passes without refreshing `reference_fake_v1`. `converse` is excluded from the "at least 3 tickets per route" coverage rule (covered by `test_m21_conversation.py`).

## Not changed
Models, embeddings, Nomic prefixes, FAQ, citation validation, abstention, router thresholds, RBAC, tickets, rate limits, WebSocket security, latency (M3).

## Needs your machine
Whether the real microphone and speech recognition produce text the patterns recognise (they tolerate punctuation loss and common variants; unusual mis-transcriptions fall back to the normal flow, which still escalates explicit person requests via the floor), and how the replies sound.
